# DNS Manager

Клиент-серверное приложение на Go для удаленного управления списком DNS-серверов на Linux-машине.

Проект состоит из gRPC-сервера и CLI-клиента. Сервер запускается на удаленном хосте, работает с файлом
`/etc/resolv.conf` и предоставляет API для добавления, удаления и просмотра DNS-серверов. Клиент подключается к серверу
и позволяет вызывать ручки API сервера.

Так как проект не содержит сложной бизнес-логики, а просто предоставляет API для записи в файл, при проектировании я
старался не усложнять архитектуру проекта.

## Возможности

- Добавление DNS-сервера по IP-адресу.
- Удаление DNS-сервера из конфигурации.
- Просмотр текущего списка DNS-серверов.
- Настройка адресов, таймаутов и пути к `resolv.conf` через переменные окружения.

## Архитектура

Серверная часть поднимает gRPC-сервис `DnsService` с методами:

- `Add` - добавляет DNS-сервер.
- `Remove` - удаляет DNS-сервер.
- `List` - возвращает список DNS-серверов.

В проекте намеренно не используется полноценная чистая архитектура. Для такого небольшого сервиса она добавила бы лишние
слои и усложнила бы код без практической пользы.

Работа с DNS-конфигурацией вынесена в репозиторий `internal/repository/resolvconf`, который читает и обновляет файл
`resolv.conf`. По умолчанию используется `/etc/resolv.conf`, но путь можно изменить через переменную окружения
`RESOLV_CONF_PATH`, что удобно для локальной разработки и тестов.

CLI-клиент построен на Cobra и предоставляет команды:

```bash
dns-manager add <ip>
dns-manager remove <ip>
dns-manager list
```

Подробную информацию можно узнать, введя команду `dns-manager --help`.

## Конфигурация

Приложение читает настройки из переменных окружения и файла `.env`.

Пример файла с описанием всех параметров находится в [.env.example](.env.example). Его можно использовать как шаблон для
локального `.env`.

## Логирование

В ТЗ отдельно требовалось предусмотреть ситуацию, когда во время работы сервера выясняется, что он работает неправильно
и нужно понять причину. Для этого в серверной части используется структурированное логирование через `zap`. Сервер пишет
в логи историю запросов и их результат.

## Запуск

Для запуска команд из `Taskfile.yml` нужен Task. Его можно установить через Go:

```bash
go install github.com/go-task/task/v3/cmd/task@latest
```

Установить зависимости:

```bash
task deps
```

Собрать сервер и клиент:

```bash
task build
```

Запустить сервер:

```bash
./bin/server
```

В отдельном терминале выполнить команды клиента:

```bash
./bin/client list
./bin/client add 8.8.8.8
./bin/client remove 8.8.8.8
```

Адрес сервера можно переопределить флагом:

```bash
./bin/client --addr 127.0.0.1:8080 list
```
